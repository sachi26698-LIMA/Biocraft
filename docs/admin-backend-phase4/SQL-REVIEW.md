# SQL and live metadata review

Read-only catalog observations on shared project `jvpadtzfsuekixrquzjv` are point-in-time, not a penetration test. Four migrations are recorded: `0001_initial_schema`, `0003_reconcile_live_to_repo`, `0002_rls_policies`, `0004_stable_bio_pagination` in provider order. The earlier 0004 was applied without the required approval and disclosed; no Phase 4 changes or remediation were made. Branch/Edge Function listings returned empty, not proof of entitlement or absence of all backend endpoints.

## Live controls and gaps

Ten public tables (`bios`, `captions`, `categories`, `emoji_collections`, `fonts`, `generators`, `hashtags`, `platforms`, `seo_pages`, `symbols`) are owned by `postgres`, RLS enabled, FORCE off; each has an active-only permissive SELECT policy for anon/authenticated. Effective privilege checks found both roles SELECT, REFERENCES and TRIGGER on all ten and no effective INSERT/UPDATE/DELETE/TRUNCATE in earlier checks. Both are NOLOGIN, lack BYPASSRLS/CREATEROLE/CREATEDB, do not belong to postgres/service_role; authenticator is a member of anon/authenticated/service_role. Both have database TEMP but not database CREATE; have USAGE and not CREATE on nine inspected non-system schemas. Neither RLS nor active-only policies controls REFERENCES, TRIGGER or TRUNCATE; owner and BYPASSRLS roles bypass ordinary RLS. `service_role` and postgres bypass RLS; do not use them in the general admin gateway.

**Priority security finding — conditional, not proven compromise:** granting TRIGGER permits creation of a trigger on the target to a SQL-capable role with EXECUTE on its trigger function; lack of CREATE in the target schema is not sufficient protection. TEMP plus trusted PL/pgSQL can permit creation of a temporary trigger function in the session. A disposable PGlite experiment (`npm run test:admin-privilege-review`) reproduced both existing-function and temporary-function attachment to a permanent fixture table with no public-schema CREATE. Temporary object lifetime and effects depend on sessions/connections; this is not proof of live Supabase exploitation. `public.set_updated_at` is an executable invoker trigger function. REFERENCES matters when a role can create a referencing relation and execute the relevant DDL, potentially including temp relations; assess constraints/side channels, not RLS alone. No arbitrary SQL endpoint, SQL-capable anon connection, or actual production trigger creation was established or tested. Investigate Data API/RPC/definer reachability and connection/role assumptions with independently authorized security testing. Treat revocation of unused REFERENCES/TRIGGER (and TEMP after impact analysis) as a separately reviewed production change, not an action authorized now.

`public.rls_auto_enable()` is postgres-owned SECURITY DEFINER event-trigger function, EXECUTE effective for guest roles; event trigger `ensure_rls` fires on `ddl_command_end`. Its event-trigger return type is not an ordinary scalar REST RPC; public EXECUTE alone is not evidence of direct invocation/exploitation. Function catches exceptions and continues, so a successful DDL is not proof RLS enabled. `search_bios` is invoker, offset-paginated with a stable tie breaker; actual access depends on grants and RLS. Listed extension trigger/event functions have varied owners/executability; no claim that all reachable definers in all schemas or all extension effects were exhaustively assessed. Default ACLs for all creators, column grants, security-definer call graphs, SQL endpoint exposure and effective access after role settings must be rechecked before any target change. Auth config, secrets, backups and all future role capabilities were not inspected or assumed.
