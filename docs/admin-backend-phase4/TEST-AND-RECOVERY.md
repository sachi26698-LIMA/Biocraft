## Incident containment and recovery runbook — to rehearse, not execute now

1. Designated operator declares incident, records time/scope, preserves logs and pages security/owner. Stop admin gateway acceptance and production worker; independently disable target receiver and its target switch, revoke worker identity, disable affected users/server sessions and provider refresh sessions; rotate affected credentials through approved provider process. Do not wait for source switch or browser logout alone. Block network egress if necessary and supported. Track currently running transactions: a revocation or switch cannot retroactively cancel committed actions and may not interrupt in-flight transactions.
2. Preserve evidence in independent sink and both databases; do not run destructive rollback. Capture outbox/receipts, target versions and delivery IDs; compare source/target to identify pending, committed, duplicate and ambiguous releases. A receiver commit with lost acknowledgment must be reconciled by receipt, never resent under a new ID. Stop on inconsistent hashes.
3. For incorrect public content, prepare a **new** target-version-checked rollback revision using last known good manifest; apply ordinary independent review, target audit and explicit production publication approval. Account for static build, CDN and fallback; don't promise removal from old offline clients. Do not restore a whole database over unrelated later changes without a separate incident decision.
4. Restore verified admin and target backups into isolated projects for inspection, compare checksums and release history; test functionality, Auth/session implications, audit and secret rotation. Never overwrite Production as a routine rollback. Provider backup scope may omit Auth configuration, secrets, external sinks, storage or deployed frontend; inventory and restore them separately. Owner must choose retention, legal hold, RPO/RTO and test frequency; capabilities/entitlement and exact measured recovery times are currently unknown.
5. Security and owner sign off root cause, re-establish least privilege, verify receiver off and independently test; separately authorize re-enable and future publication. Retain incident records per approved policy.
