## Explicit missing migration/code items before any functional or Production deployment

1. Least-privilege non-bypass owner/executor roles, default privileges for each actual creating owner, audit policy, role inheritance and exposed-schema review. RLS cannot constrain superusers, owners without FORCE RLS or `BYPASSRLS`; `SECURITY DEFINER` ownership and function grants must be reviewed together. Note FORCE RLS alone does not constrain superusers/BYPASSRLS.
2. Provider-verified identity/session binding, recency of MFA and revocation checks, scoped permission functions and narrowly granted server entry points. If the gateway connects as a service role, RLS is bypassed; require an alternative least-privileged design and direct-access tests.
3. Typed resource schemas and adapters (all bio derived fields, language and independent platform limits, categories, collections, platforms, generators, libraries, settings, SEO). Exact stable-key mapping, backfill, schema/versioning, cycle and ownership constraints. The generic JSON payload is not authorization or validation.
4. SQL to reserve idempotency keys and commit result; optimistic version locks, mutation/submit/review state machine with immutable submitted snapshots, author/reviewer separation and serialized final-S invariant; transactional success audit. No approved hard-delete mechanism exists.
5. Target-specific release adapter and kill-switch enforcement, DB+audit atomicity, cross-DB outbox/receiver and target audit when applicable, versioned public consumers and static SEO/cache/tombstone strategy; all require explicit approval before touching shared content. No generic DDL can make bundled assets dynamic.
6. Real audit sink delivery, retry/monitoring/retention and denied-event logging outside rolled-back transactions; job leases, bulk item outcomes, secure object storage/export expiry, privacy-approved telemetry ingestion, small-cell suppression and retention. A metadata table is not a worker or provider.
7. Exact backup, restore, content-reversal, operational rollback and owner/key revocation scripts for the chosen provider; restoration tests and RPO/RTO; index selection after representative plans. Protect audit retention; do not claim a backup exists until verified.

## Local-only fixture validation

`npm run test:admin-phase3-schema` loads 001 through 004 into disposable PGlite with synthetic Auth and public fixtures, checks all 16 private policies are restrictive, guest active-only fixture, role examples, invalid state/length constraints, direct-role denials and a deliberate permissive-grant simulation still constrained by restrictive deny. It executes 098 only against the disposable fixture. `npm run test:admin-blueprint` and `npm run typecheck` also pass. PGlite mocks `auth.uid()` and `auth.jwt()`; these results do **not** establish actual Supabase privileges, provider JWT verification, MFA freshness, external services, concurrent transactions, real PostgreSQL behavior, safe publishing or production readiness.
